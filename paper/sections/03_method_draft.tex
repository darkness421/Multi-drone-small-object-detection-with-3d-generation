\section{Method}
\label{sec:method}

\subsection{Overview}
\label{sec:method_overview}

CoM3D-ACE is designed around one principle: ambiguous UAV detections should be
converted into explicit evidence before they are fused, completed, or reasoned
over. Given synchronized UAV observations
$\mathcal{I}=\{(I_i, K_i, T_i, t_i)\}_{i=1}^{N}$ with image $I_i$, camera
intrinsics $K_i$, camera pose $T_i$, and timestamp $t_i$, the system first
extracts 2D object evidence with SAFR-YOLO. Each detection is then represented
as an EvidenceToken and inserted into a cross-view 3D evidence graph. The graph
assigns confident hypotheses to a verified object state and sends ambiguous
hypotheses to 3D completion, re-observation, and AeroGraph reasoning.
The two validation checks are intentionally separated: system verification tests
whether the graph, geometry, uncertainty, and completion evidence are
consistent, while action verification tests whether a proposed follow-up action
is allowed by the evidence graph and safety constraints.

\subsection{SAFR-YOLO 2D Evidence Generator}
\label{sec:method_safr_yolo}

SAFR-YOLO follows a YOLO-family backbone--neck--head structure but changes the
small-object prediction path. The P2/P3/P4 feature maps are used as the primary
detection heads, while the P5/32 branch is retained as semantic context rather
than a final small-object prediction head. This matches the observation that
very coarse feature maps are weak for tiny aerial targets.

The selected implementation, P2P4-SelfAttnFR, adds SelfAttnFR refinement before
the detection heads. SelfAttnFR has two lightweight paths. The first path pools
the spatial feature map into a small set of tokens and applies self-attention to
capture adjacent-object context at low cost. The second path applies local
refinement and TinyFReLU to preserve high-frequency edge and texture cues. The
two paths are fused with a $1\times1$ projection before detection.

\begin{figure*}[t]
\centering
\includegraphics[width=0.98\textwidth]{figures/fig02_p2p4_safr_yolo.png}
\caption{SAFR-YOLO detector structure. P2/P3/P4 heads provide high-resolution
small-object predictions, SelfAttnFR refines adjacent-object context and local

\label{fig:safr_yolo}
\end{figure*}

The main figure emphasizes where the proposed detector changes the YOLO
pipeline. The supplementary material provides separate module diagrams for
SelfAttnFR, TinyFReLU, and overlap-aware NMS, including the internal data flow
and decision cues used by each component.

For an input feature $F\in\mathbb{R}^{H\times W\times C}$, TinyFReLU uses a
depthwise spatial condition and a high-frequency residual:
\begin{equation}
h(x)=x-\mathrm{AvgPool}_{3\times3}(x),
\end{equation}
\begin{equation}
c(x)=\mathrm{BN}(\mathrm{DWConv}_{3\times3}(x))+\tanh(\gamma)h(x),
\end{equation}
\begin{equation}
y=\max(x,c(x)).
\end{equation}
This keeps the activation close to a lightweight FReLU-style gate
\cite{ma2020frelu} while adding an explicit residual cue for weak tiny-object
boundaries. The overlap-aware post-processing used in SAFR-YOLO is evaluated
against standard NMS and Soft-NMS-style alternatives \cite{bodla2017softnms}
to avoid suppressing adjacent tiny objects solely because their boxes overlap.

\subsection{EvidenceToken Representation}
\label{sec:method_evidence_token}

Each detector output is converted into an EvidenceToken:
\begin{equation}
\tau = (b, p, s, u, f, v, T, t),
\end{equation}
where $b=(x,y,w,h)$ is the bounding box, $p$ is the class-logit vector, $s$ is
the confidence score, $u$ is an uncertainty descriptor, $f$ is an optional crop
or feature descriptor, $v$ is the UAV/view identifier, $T$ is the camera pose,
and $t$ is the timestamp. This representation keeps the detector output
compatible with ordinary 2D evaluation while exposing the fields required for
cross-view association and ambiguity-aware decision making.

\subsection{Cross-View 3D Evidence Graph}
\label{sec:method_evidence_graph}

The EvidenceTokens are associated into a graph
$\mathcal{G}=(\mathcal{V},\mathcal{E})$. Observation nodes represent 2D tokens,
and object-hypothesis nodes represent candidate 3D object states. For token
$\tau_i$, we lift the 2D box center $\tilde{x}_i=(x_i,y_i,1)^\top$ to a camera
ray
\begin{equation}
r_i=\frac{R_i K_i^{-1}\tilde{x}_i}{\|R_i K_i^{-1}\tilde{x}_i\|_2},
\end{equation}
and obtain an approximate association point
\begin{equation}
q_i=c_i+\eta_i r_i .
\end{equation}
Here $c_i$ is the camera center and $\eta_i$ is read from depth when available;
otherwise the MarineCity validation protocol uses a ground-plane intersection. These
points are used for association and decision-policy diagnostics, not as metric 3D
ground truth.

An observation supports a hypothesis $o$ when its class agrees and its lifted
point lies within a support radius:
\begin{equation}
e^{\mathrm{sup}}_{i,o}=1
\quad \mathrm{if}\quad
y_i=y_o \ \mathrm{and}\ \|q_i-\mu_o\|_2 \le \delta_s .
\end{equation}
Two hypotheses form a conflict edge when they are spatially close but assign
different classes,
\begin{equation}
e^{\mathrm{conf}}_{o,o'}=1
\quad \mathrm{if}\quad
y_o\ne y_{o'} \ \mathrm{and}\ \|\mu_o-\mu_{o'}\|_2 \le \delta_c ,
\end{equation}
and a missing-evidence edge is added for any expected UAV view that has no
supporting token for $o$. Thus the graph explicitly records support,
class/geometric conflict, and missing views instead of passing raw detections
directly to the reasoner.

We use a bounded ambiguity score
\begin{equation}
A(o)=\mathrm{clip}\big(
\bar{u}_o
+0.18\mathbf{1}[n_o<2]
+0.08\mathbf{1}[\sigma_o>\delta_s/2]
+0.06\mathbf{1}[b_o>0.15],\,0,\,1\big),
\end{equation}
where $\bar{u}_o$ is mean detector uncertainty, $n_o$ is the number of
supporting UAV views, $\sigma_o$ is association spread, and $b_o$ is the
largest invalid-pixel ratio among supporting crops. The ambiguity-aware
decision policy is
\begin{equation}
\pi(o)=
\begin{cases}
\mathrm{reject}, & n_o<2 \ \mathrm{and}\ \bar{s}_o<0.03,\\
\mathrm{finalize}, & n_o\ge2 \ \mathrm{and}\ A(o)<0.55,\\
\mathrm{monitor}, & n_o\ge2 \ \mathrm{and}\ 0.55\le A(o)<0.75,\\
\mathrm{reobserve}, & \mathrm{otherwise}.
\end{cases}
\end{equation}
Only the high-ambiguity subgraph and its allowed actions are sent to the
AeroGraph Reasoner. The reasoner suggests class belief, evidence needs, and an
action; it does not directly control the UAV. A graph-and-safety verifier checks
the suggestion before the action is accepted.

The active follow-up routes are defined by two binary gates. Let $c_o$ and
$m_o$ denote the numbers of conflict and missing-evidence edges incident to
hypothesis $o$. The targeted re-observation gate is
\begin{equation}
g_{\mathrm{view}}(o)=
\mathbf{1}\!\left[A(o)\ge0.75 \ \lor\ (m_o>0 \land A(o)\ge0.55)\right],
\end{equation}
and the graph-grounded reasoner gate is
\begin{equation}
g_{\mathrm{reason}}(o)=
\mathbf{1}\!\left[A(o)\ge0.55 \land (c_o>0 \lor m_o>0 \lor n_o<2)\right].
\end{equation}
Thus, re-observation is selected when the current views are insufficient for a
stable object state, while AeroGraph is invoked only for graph hypotheses whose
uncertainty, conflicts, or missing views require an explicit evidence-based
decision. Hypotheses that are rejected by the low-confidence rule are filtered
before the reasoner, and finalized hypotheses bypass both active routes.

\subsection{MarineCity 3D Evidence Completion And AeroGraph Reasoner}
\label{sec:method_3d_reasoner}

For MarineCity experiments, the system exports real-Cesium RGB/depth/pose
captures and a NeRF-style transforms package. Neural-3D runners are used to
test whether the capture package can support held-out viewpoint reconstruction
and completion. The resulting 3D evidence is not treated as a replacement for
2D detection; it is used as additional context for ambiguous object hypotheses.

\begin{figure*}[t]
\centering
\includegraphics[width=0.98\textwidth]{figures/fig03_3d_evidence_reasoner.png}
\caption{3D evidence completion and AeroGraph Reasoner interface. The current
paper reports real-Cesium system/protocol validation, evidence-graph action
diagnostics, and neural-3D runner-family validation metrics while keeping final
action decisions gated by graph and safety verification.}
\label{fig:marinecity_3d_reasoner}
\end{figure*}

The AeroGraph Reasoner receives a compact graph-grounded package containing the
high-ambiguity subgraph, supporting and conflicting crops, a geometry summary,
and allowed actions. It returns a structured decision containing class belief,
confidence, evidence needs, and a proposed action. A graph-and-safety verifier
checks whether the action is consistent with the evidence graph and physically
plausible before it is accepted.
