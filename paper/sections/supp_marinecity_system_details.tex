\paragraph{Re-observation-policy analysis.}
Table~\ref{tab:supp_marinecity_reobservation_policy_ablation} compares simple
decision policies over the same graph hypotheses. The proposed graph policy is
selective: it does not send every detector box downstream, but it still handles
all high-ambiguity hypotheses through either targeted re-observation or
rejection. This is the main efficiency benefit of the system layer: the
detector produces 78 token-level observations, whereas the graph exposes 17
decision units and 9 targeted re-observation actions.

\paragraph{Graph construction and decision-policy details.}
The supplementary graph uses the same EvidenceToken fields as the main method:
2D box center, class belief, confidence, detector uncertainty, UAV identifier,
camera intrinsics, camera extrinsics, and UAV pose. Each token is projected to a
camera ray and associated to the ground-plane or available depth point. Tokens
with matching classes are clustered within a support radius
$\delta_s=55$ scene units; nearby different-class hypotheses within
$\delta_c=38$ scene units create conflict edges. Missing-evidence edges are
added when a hypothesis lacks support from an expected UAV view. The ambiguity
score follows the main method definition: low-confidence
single-view hypotheses are rejected, multi-view hypotheses with moderate
ambiguity are monitored, and high-ambiguity or missing-view hypotheses are sent
to targeted re-observation. In the current viewer160 protocol, the graph
compresses 78 detector tokens into 17 hypotheses and records 78/11/25
support/conflict/missing-evidence edges with action counts
F/M/R/O = 0/1/7/9.

\paragraph{Nerfacto-sweep analysis.}
Table~\ref{tab:supp_marinecity_nerfacto_sweep} and
Fig.~\ref{fig:supp_marinecity_nerfacto_sweep} provide the supporting evidence
behind the representative Nerfacto row in the main paper. The full-resolution
24k run is retained because it gives the most stable SSIM/LPIPS among the
paper-facing capture settings. A standard 12k run reaches slightly higher PSNR,
but it is treated as an auxiliary sweep row because it is not the same
full-resolution validation setting. The 32k reinforcement run decreases PSNR,
SSIM, and LPIPS, so it is explicitly retained as a non-promoted auxiliary
result rather than being mixed into the main 3D method table.

\paragraph{Depth-view consistency analysis.}
Fig.~\ref{fig:supp_marinecity_depth_view_consistency} checks whether the
captured RGB/depth/pose package can support cross-view evidence transfer before
neural rendering is considered. The sanity check reaches a mean projected fill
ratio of approximately 0.328 across the three scenarios, which is sufficient
for visualizing coarse overlap and missing-view regions. Because the projection
is depth-backed but not optimized by a neural field, we use it only as
supporting evidence for the 3D evidence graph and not as a reconstruction
quality metric.
